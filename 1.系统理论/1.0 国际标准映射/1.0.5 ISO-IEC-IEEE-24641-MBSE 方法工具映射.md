## 1. 标准概述

| 属性 | 内容 |
|---|---|
| 标准名称 | ISO/IEC/IEEE 24641:2023 — Systems and Software engineering — Methods and tools for model-based systems and software engineering |
| 发布机构 | ISO / IEC / IEEE |
| 版本 | 2023（Edition 1，2023-05 发布） |
| 官方链接 | <https://www.iso.org/standard/79111.html> |
| 访问日期 | 2026-07 |
| 适用范围 | 规定 MBSSE（Model-Based Systems and Software Engineering）的方法与工具能力；定义 MBSSE 参考模型，包括 Plan MBSSE、Build Models、Perform MBSSE 等过程组，以及工具能力要求 |

> 权威说明：标准强调 MBSSE 是以不断演化的模型作为系统/软件实体主要知识源的工程方法，区别于传统的“用模型进行工程”。来源：[ISO/IEC/IEEE 24641:2023(en)](https://www.iso.org/obp/ui/es/#!iso:std:79111:en)、[ANSI Blog](https://blog.ansi.org/iso-iec-ieee-24641-2023-model-based-systems-methods/)。

## 2. MBSSE 参考模型与项目映射

ISO/IEC/IEEE 24641:2023 将 MBSSE 参考模型划分为四个过程组。下表将其映射到项目七维框架与相关文件。

| 24641 过程组 | 主要内容 | 项目覆盖章节 | 当前覆盖状态 | 关键缺口 |
|---|---|---|---|---|
| **Plan MBSSE** | 建模先决条件、范围评估、策划 | `1.1 知识梳理`、`1.3 形式化结构` | 未覆盖 | 缺少建模目的、范围与利益相关者约定的显式定义 |
| **Build Models** | 模型构建、模型验证与确认（V&V）、模型转换 | `1.3 形式化结构`、`1.4 形式化证明`、`1.5 多表征` | 部分覆盖 | 模型作为“主要知识源”的地位未明确；模型转换规则缺失 |
| **Perform MBSSE** | 评估、技术管理、模型使用（分析、综合、决策） | `1.2 批判分析`、`1.6 形式语义`、`1.8 系统运行时语义` | 部分覆盖 | 缺少基于模型的决策管理与运行时模型联动 |
| **Support MBSSE** | 工具能力、配置管理、质量保证 | `1.5 多表征`、`tools/` 形式化工件 | 部分覆盖 | 工具链与模型版本管理未对齐标准 |

## 4. 关键覆盖缺口

1. **MBSSE 作为“模型即主要知识源”的理念未显式化**：`1.3 形式化结构` 与 `1.5 多表征` 将模型视为辅助表示手段，未明确模型是系统全生命周期知识的主来源。
2. **模型 V&V 与模型转换规则缺失**：`1.4 形式化证明` 主要面向定理证明，缺少针对模型本身的一致性、完整性、正确性验证，以及模型到代码/运行时的转换规则。
3. **MBSE 工具能力映射缺失**：项目虽拥有 Coq/Isabelle/TLA+/UPPAAL 等工件，但未按 24641 工具能力要求（如建模、仿真、代码生成、配置管理）进行系统梳理。
4. **模型版本与配置管理未覆盖**：`1.7 递归展望与参考文献` 未将模型制品纳入配置管理视角。
